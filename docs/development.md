## 第 6 段实现

- `src/sync.ts` 提供单房间同步批次，使用原生 `/sync` 游标；截断段通过 `/messages` 的原生区间分页补齐，保持事件顺序与事件 ID。
- `src/local-sync.ts` 提供 CLI 的进度文件、输出后保存、运行中断连重试与退出清理；消息仍由 Synapse 保存。进度以服务器、账号、设备、房间为范围；并发进程复用 `proper-lockfile`，文件写入复用 `write-file-atomic`。
- SDK 默认同步循环会先推进内部 token 再处理事件，因此本模块显式返回批次，由宿主处理成功后提交游标，不启动完整事件缓存或第二套消息引擎。
- 首次同步是最近消息快照；后续才是增量补收。正常重启不重播已提交批次，但处理与提交之间崩溃可重投，不承诺业务执行恰好一次。

协议依据：[同步与增量](https://spec.matrix.org/latest/client-server-api/#get_matrixclientv3sync)、[补齐时间线缺口](https://spec.matrix.org/latest/client-server-api/#get_matrixclientv3roomsroomidmessages)。SDK 的 HTTP 层虽为 public，源码标注 intended private，固定在 `matrix-js-sdk@45.0.0` 并集中用于同步模块，升级时需复核。

### SDK 退出延迟补丁

源码定位到 SDK 的 `timeoutSignal` 使用未释放的普通计时器，使成功完成的 Node CLI 仍等待超时。`patches/` 的小补丁优先使用原生 `AbortSignal.timeout`，不具备该 API 的环境保留原行为；pnpm 按固定版本应用，无需维护 SDK fork。
本机相同身份查询的进程耗时由 10300 ms 降至 302 ms；实际 HTTP 请求两次均为 22 ms。这是一组本地对照，不代表通用网络性能。
补丁同时覆盖 SDK 源码和当前运行的编译文件，可作为上游贡献候选，尚未公开提交。

### 实连结果与复现

- B 运行 `pnpm chat sync --peer --once --limit 1` 建立快照并退出；A 随后发送三条消息。B 用同一命令恢复，`backfilled: true` 且按原顺序收到全部三个事件。再次运行得到空批次。
- B 持续同步期间启动第二个相同范围的同步进程，被明确拒绝。停止 Synapse 后原进程进入重试，进度文件保持不变；服务恢复后自动收到 A 的新消息并保存游标。
- Ctrl+C 正常退出并释放锁，再运行 `--once` 未重播已确认事件。私有进度文件权限为 `600`；类型检查通过，无新增测试框架或测试代码，无模型调用。
- 原始命令、输出与状态码保存在 `.local/learning-replay/stage-6.json`；基线源码、私有会话与数据库快照在 `before-stage-6-*/`。

实测范围为本地 Synapse、一个明文房间和两个普通账号。首次快照不是完整历史；接收后、保存游标前崩溃仍可能重投。宿主需按事件 ID 幂等处理，不将接收成功等同于任务执行成功。
