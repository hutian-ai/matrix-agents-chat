# 验证与复现

验收使用真实 Matrix / Synapse、Docker PostgreSQL 和实际 Dock / Codex，不用模拟回复证明模型成功。没有新增测试框架、fixture、自动化测试矩阵或 CI。

环境：macOS arm64、Node.js 22.23.3、pnpm 11.9.0、Docker / Colima、Synapse v1.164.2、PostgreSQL 18.6。执行设备由 Harness Dock App 的本机候选管理。以下范围不推广到未经验证的 Provider、设备或生产规模。

## 已实测

| 项目 | 真实步骤 | 结果 |
| --- | --- | --- |
| 多成员 | 创建只含一位助手的房间，再邀请第二位 | 实际成员从两位变为三位，邀请本身无模型调用 |
| 独立回复 | 同一原文先后交给两位助手 | 两个 Matrix 署名、两个运行 ID 和原生关联回复 |
| 人工转交 | 引用协作助手原文，附上人的评审要求，交给另一位 | 实际提示词包含要求与引用原文，得到真实评审 |
| 发送中刷新 | 请求已写入 Matrix、页面尚未确认时刷新 | 沿原事务重试后仍只有一条人类指令 |
| 运行中刷新 | Dock 运行已建立回执后刷新网页 | 观察原运行，不创建替代任务 |
| 运行中强制重启网页后端 | 确认独立宿主存活与 Dock 回执后，对已核对入口的网页进程 SIGKILL，再重启 | 独立宿主仍存活，原活动 / 运行 ID 保留，最终原生回复送达，没有替代执行 |
| 重复操作 | 同一 Agent / 房间 / 消息重复处理 | 原运行、原回复和消息数量保持一致 |
| 权限 | 未入房助手、跨房间事件、Agent 原文直接执行 | 分别被拒绝，不创建替代运行 |
| 干净安装：共享数据库 | 干净源码目录安装依赖、指定独立 DB / 非管理员账号 | 从零启动 Synapse，三个身份和默认房间就绪 |
| 干净安装：自带数据库 | 干净源码目录运行默认 Docker 安装 | PostgreSQL / Synapse 均健康，应用角色无 superuser / createdb / createrole 权限 |
| 无密码身份 | 通过 AS 创建身份，用返回的普通用户会话收发 | 无需逐个填写密码，返回会话不是 AS 总令牌 |
| 身份范围 | AS 请求范围外 localpart、普通用户令牌代建 | `M_EXCLUSIVE` / `M_UNKNOWN_TOKEN`，没有越权创建 |
| SDK 仓库外消费 | 将实际 0.1.0 tarball 安装到仓库外目录，编译独立 TypeScript 消费端并读取实际历史 | 八个函数可导入，类型与两条真实历史读取通过，无相邻源码依赖 |
| SDK 通信 | 无 Dock 的独立宿主收消息、补收、关联回复、重试发送 | 真实历史与原生回复关系正确，重试返回同一事件 |
| 停止再启动 | 停止 / 启动共享数据库模式和默认安装 | 已有消息 ID 一致；已完成任务的网页服务重启后保留原回执 |
| 旧数据 | 升级前后核对原有房间与 CLI `--status` | 原成员、消息和运行对应关系保留 |
| 布局 | 桌面与 390 像素窄屏实际操作 | 可打开成员、切换房间与回复对象；窄屏无横向溢出 |

### 修复前的真实失败

第一次运行中重启验证暴露旧实现的问题：网页进程中止会关闭 SDK 应用连接，原记录最终为 `failed / application_disconnected`，没有继续完成。该失败记录保留，未重新派发同一事件。随后改为独立宿主持有连接，以新的人类指令重新验证：强制终止网页进程后，宿主继续存活，原运行最终关联回复。此结果只覆盖网页进程故障，不扩展成“宿主 / Dock / 原生 Harness 任意故障均继续执行”。

最终打包、仓库外消费、运行中强制重启与交付检查的原始结果在 `.local/learning-replay/stage-15/`。

## 第三个人复现

1. 按 [部署说明](deployment.md)从干净目录运行 `pnpm install --frozen-lockfile`、`pnpm local:setup`、`pnpm doctor`、`pnpm web`。默认房间应有一位操作者和两位已准备身份的助手；尚未配置执行宿主时，网页不能伪装出 AI 回复。
2. 按 [SDK](sdk.md)用一位助手自己的会话读取、回复一条消息，并沿同一 `transactionId` 再发送，核对事件 ID；用 `syncRoom` 保存游标后继续补收。
3. 按 [Dock 接入](integration.md#在新环境配置-dock-宿主)准备自己的设备 / 原生登录，配置两位助手。网页发送消息后无任务，手动指定才有真实回复；随后转交一条 Agent 回复。
4. 刷新页面、重复操作原消息，查看仍是同一运行和回复；需复现运行中重启时，先确认已取得回执与独立宿主锁，再停止网页进程并重启，核对同一运行及最终回复。不要终止独立宿主、设备后台或借保存的 PID 杀进程。断连和超时不能被当作取消。
5. 对独立安装执行 `pnpm local:stop`、`pnpm local:up`，核对历史与成员；备份数据库和私有身份 / 回执后再做任何恢复操作。

`pnpm check`、`pnpm web:build`、`pnpm build` 是类型和构建检查，不代表所有业务路径都通过。模型请求仅针对所列真实场景，不将返回普通文本或协议 ready 计为全部工具能力成功。

## 交付文件检查

固定版本的 Gitleaks 已扫描完整 Git 历史且未发现凭据；另外对本机实际私有凭据值检查了源码、未推送历史、网页产物与 SDK tarball。当前 Git 代码树不再跟踪 `.local`；本机旧源码快照保留，远端原有历史没有强推重写。扫描是有限范围的检查结果，不替代接入方对自己配置和发布内容的复核。

## 适用范围

当前网页固定一位本机操作者，文本明文通信。SDK 宿主可映射自己的用户和 Agent，但仍负责业务授权、预算、工具、长期记忆和项目事实。

本轮不承诺多用户远程部署、跨设备去重、恰好一次执行、任意模型兼容、加密文本解密或完整游戏世界。未执行公共发布动作；仓库保持私有。
