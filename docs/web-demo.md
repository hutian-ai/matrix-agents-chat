# 网页聊天

这是支持创建与切换房间、邀请多位助手并指定回复对象的本机使用入口。它使用现有 SDK 与 Dock 宿主，房间、成员与消息由 Synapse 保存，原任务与回执仍放在宿主自己的 `.local/agent-host/`。

## 启动与使用

首次安装先运行 `pnpm local:setup`，自动准备服务、身份和房间；已有手工环境继续使用原配置。真实模型回复另按 `examples/dock-host.env.example` 配置私有宿主，并在助手列表条目引用该文件；未接入执行的助手只经外部 SDK 交流，网页执行入口禁用。

```sh
pnpm web
```

命令构建网页并启动本机服务，默认地址为 http://127.0.0.1:3310。输入消息并发送后，右侧会选中这条消息。在“由谁回复”中选择一位已加入的助手，点击“让所选助手回复”才触发一次真实运行，会使用原生模型账户额度；该助手以自己的 Matrix 身份关联回复。切换回复对象可让另一位助手独立回应同一条消息。

左侧点击“新建聊天室”，填写名称并选择一起加入的助手，即可创建邀请制明文房间。也可先只建房间，再通过“邀请助手”或顶部“成员”入口添加。列表显示当前使用者已加入的明文房间，窄屏使用标题下方的下拉框切换。创建未确认时可沿原请求继续，固定的 Matrix 别名使重试回到原房间，并继续完成邀请和加入。

点击自己的其他消息可以切换选择。草稿、选中消息、回复对象与待确认发送按房间保存在浏览器当前会话中，刷新后回到原房间。执行中仍可切换房间、浏览和发消息，界面会指出助手在哪个房间工作；同一宿主连接一次只处理一个请求。页面刷新不会发起替代运行；当前房间已有回执的未完成请求会自动核对原任务并收取可确认的最终结果，未打开房间的记录在进入该房间后核对。

从终端启动时 Ctrl+C 只停止网页服务，独立宿主继续持有 Dock 应用连接并交付原结果。再次启动网页后读取原成员、消息、宿主活动锁和回执，不重新派发。独立宿主本身或其 Dock 连接若中断，执行可能失败或结果未知，应以原回执核对；不能把关网页当作取消。没有回执时保持待核对，不推断“未执行”，也不自动重新派发。

点击 Agent 回复下方的“转交给其他助手”，选择目标并填写要求，再点击“发送并交给助手”。这会先记录一条由你署名的引用消息，再触发目标助手；仅打开转交编辑不会执行。发送未确认时沿原事务重试，执行未确认时根据这条人类指令核对原运行。

## 职责与数据

| 部分 | 作用 | 持久数据 |
| --- | --- | --- |
| Vue 网页 | 房间、邀请成员、选择回复对象、消息和执行状态 | 浏览器当前会话内按房间保存草稿、回复对象、选中项与待确认发送的事务 ID，不保存认证凭据 |
| H3 本机接口 | 固定的人类身份、助手配置映射、原生成员校验与同来源操作入口 | 复用本机私有会话；投影独立宿主锁与私有观察结果，不建立本地房间目录 |
| 可复用宿主函数 | 发送者授权、原请求对应关系、Dock 执行与结果收取 | 沿用原操作文件、SDK 回执、准备中的回复与固定事务 ID |
| Matrix SDK / Synapse | 发送、原生回复和历史 | 消息、身份、成员关系由 Synapse 保存 |

当前宿主每次提交选中的消息正文；该消息带有原生引用时，额外读取并提交一条有权访问的引用原文。它不自动加入整个房间的历史，也未实现长期记忆。

网页通过独立 Node 宿主运行 Dock 调用，日志与观察结果直接写入私有文件；网页不持有该应用连接。HTTP 请求结束、浏览器关闭或网页进程重启均不结束独立宿主。宿主 CLI 与网页复用同一执行函数和连接锁，避免并行观察抢占同一 Dock 应用连接。每次新请求先保存宿主标识，SDK 再保存回执；`resumeOnly` 路径要求原记录已存在，只查询原运行。

发送未确认时，网页保留当前文本与事务 ID，点击“重试发送”沿用它。Matrix 原生事务机制仍以本机配置的同一账号和设备为范围；没有新增跨设备业务去重承诺。

## 当前边界

这是本机服务，固定绑定回环地址，并核对 Host、提交来源、JSON 类型与消息发送者。读取和发送要求当前使用者已加入所选房间；执行再检查所选助手已加入，原消息必须属于该房间且由当前使用者发送。助手必须来自服务端已配置列表，网页不接受新的账号、凭据、文件路径或执行命令。它不是已发布的第三方 HTTP API，也没有多用户登录与完整远程访问控制。

当前使用者仍是固定的一位，助手各有独立 Matrix 身份和宿主配置。已配置的“协作助手”与“评审助手”都通过同一个 Dock 应用和设备使用 Codex，区别在于聊天身份和回复要求；这不代表独立设备、工作目录、工具权限或长期记忆。每份配置可以指定 Provider、模型或设备，但本段仅实测了同设备的 Codex，尚未实现多人登录管理。新建房间不改变 CLI 的默认房间文件，CLI 进入其他房间使用现有的 `--room` 参数。

当前读取最近 100 条明文文本消息；更早消息可用 CLI / SDK 分页读取。CLI 和网页的会话应由同一个本机宿主独占使用，不与另一个持有相同 Dock 应用身份的产品并行连接。无密码身份与独立安装见 [SDK](sdk.md)和[部署说明](deployment.md)；公开发行不在本次私有推送范围。

真实执行仍遵循原生 Harness 权限。本例提示词要求只回复文字，非交互 CLI 拒绝原生审批请求，提示词本身不构成工具隔离。

## 接入更多助手

推荐由可信宿主使用 `provisionIdentity` 自动创建受管身份并保存返回会话，见 [SDK 身份接入](sdk.md#身份)。公开注册保持关闭。若接入既有普通账号，也可沿用以下登录流程；管理员使用 Synapse 官方 `register_new_matrix_user` 准备账号。

1. 将 `matrix-peer.env.example` 复制为 `.local/matrix-reviewer.env`，填写新助手自己的账号、密码和设备 ID，文件权限设为 `600`。
2. 运行 `pnpm matrix:login --profile reviewer`。它保存 `.local/matrix-reviewer-session.json`，不会覆盖原使用者或协作助手的会话。
3. 如需网页触发真实执行，复制 `examples/dock-host.env.example` 为 `.local/reviewer-host.env`，配置该助手使用的 Dock 连接、允许的人的 Matrix ID，以及可选的 `HOST_INSTRUCTIONS`、`DOCK_PROVIDER`、`DOCK_MODEL`、`DOCK_NODE_ID`。回复要求属于宿主配置，不是工具权限控制。
4. 将 `examples/agents.example.json` 复制为 `.local/agents.json`，为每个助手指定稳定的 `id`、名称和会话文件；需网页执行时再增加 `hostConfigFile`。各助手须有不同的 Matrix 用户 ID，并与使用者连接同一 Synapse；所有引用的文件须位于本项目 `.local/`。
5. 将私有文件权限设为 `600`，重新启动 `pnpm web`。创建房间时选择助手，或在已有房间邀请。邀请入口会由受管助手自己的会话接受邀请，不触发执行。

没有 `.local/agents.json` 时，继续使用原来的 `matrix-peer-session.json` 与 `agent-host.env`，默认配置 ID 为 `assistant`。配置文件错误会阻止启动，不会悄悄退回其他身份。

这些文件只记录本机受管身份与执行方式，房间的真实成员关系仍由 Matrix 管理。未接入宿主的普通成员也会按真实身份显示，但不能在执行选择框中冒充已配置助手。

CLI 指定配置列表中的助手：

```sh
pnpm agent --agent reviewer --room '!实际房间ID' --event '$人的原消息ID'
pnpm agent --agent reviewer --room '!实际房间ID' --event '$同一消息ID' --status
```

省略 `--agent` 时使用配置列表第一位；省略 `--room` 时仍使用原本的默认房间。多个助手共享本应用 Dock 连接时保持串行；网页和 CLI 使用同一个连接锁，不并行连接同一应用身份。

## 复现本段结果

1. 按上面步骤配置至少两位助手，运行 `pnpm web`。新建“协作评审”，只选“评审助手”，确认房间成员只有你与它。
2. 发送一条文本，确认没有自动任务。在“成员”或“邀请助手”中邀请协作助手，成员变为三位，仍没有自动任务。
3. 选中同一条消息，先让评审助手回复；等完成后选择协作助手，再手动让它回复。应看到两个不同署名的原生关联回复，以及各自的运行记录。
4. 执行中切换回复对象并刷新，确认已完成助手的回复与正在执行助手的记录各自保留。完成后重复处理任一助手的原事件，应复用该助手自己的运行和回复。
5. 在任务完成后停止并重启网页服务，确认成员、消息与两份回执仍从 Matrix / 本地记录恢复。原有房间的成员与消息应保持原样。

本机第 12 段原始证据位于 `.local/learning-replay/stage-12/`；之前的多房间证据在 `stage-11/`。当前适用范围为明文文本、固定一位使用者、两位独立 Matrix 助手和同一 Dock 设备上的 Codex。第 15 段已补验运行中强制终止网页后端并恢复原任务；独立宿主终止、不同 Provider / 设备与生产规模不在同一保证范围。

## 实现参考

HTTP 路由与监听使用 [H3](https://h3.dev/guide)，静态文件使用 [srvx](https://srvx.h3.dev/)；页面采用 [Vue](https://vuejs.org/guide/quick-start.html) 和 [Vite](https://vite.dev/guide/)。核心 SDK 的依赖和返回值保持原来的通信边界。
